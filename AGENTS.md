# AGENTS.md

NestJS 11 task manager (gestor-tareas). TypeScript, ESM modules, Prisma 7, PostgreSQL.

## Commands

```bash
pnpm install              # install deps (pnpm, not npm/yarn)
pnpm run start:dev        # dev server with hot-reload on port 3000
pnpm run build            # compile to dist/
pnpm run lint             # eslint + prettier --fix
pnpm run test             # unit tests (jest)
pnpm run test:e2e         # e2e tests (jest, test/jest-e2e.json)
pnpm run test:cov         # coverage report
pnpm run format           # prettier on src/ and test/
pnpm prisma generate      # regenerate Prisma client after schema changes
pnpm prisma migrate dev   # create/apply migrations
pnpm prisma studio        # open Prisma Studio (DB GUI)
```

## Key conventions

- **Package manager:** pnpm. Lock file is `pnpm-lock.yaml`.
- **Module system:** `"module": "nodenext"` in tsconfig. Use `.js` extensions in imports (e.g. `./app.module.js`). NestJS schematics handle this, but manual imports must follow it.
- **Strict-ish tsconfig:** `strictNullChecks: true`, but `noImplicitAny: false` and `strictBindCallApply: false`. Don't enable stricter rules without team agreement.
- **ESLint:** Flat config (`eslint.config.mjs`). Uses `@typescript-eslint/recommended-type-checked` with `no-explicit-any: off`. Prettier runs as ESLint rule.
- **Prettier:** `singleQuote: true`, `trailingComma: "all"`.
- **Testing:** Jest 30 with ts-jest. Unit tests colocated as `*.spec.ts` in `src/`. E2E tests in `test/`.
- **Build:** `nest build` outputs to `dist/`. `nest-cli.json` sets `deleteOutDir: true`.
- **Scaffolding:** `nest g resource <name>` creates controller, service, module, DTOs, and tests in one go.

## Prisma 7 specifics

- **Generator:** `prisma-client` with output to `src/generated/prisma` and `moduleFormat = "cjs"`.
- **Adapter:** Uses `@prisma/adapter-pg` with `PrismaPg` in `PrismaService` constructor.
- **Imports:** Always from relative paths within `src/`:
  ```typescript
  import { PrismaClient } from '../generated/prisma/client';
  import { Rol, EstadoTarea, Prioridad } from '../generated/prisma/enums';
  import type { Usuario, Tarea } from '../generated/prisma/models';
  ```
- **Never import from `@prisma/client`** — Prisma 7 generates to a custom output directory.
- **Schema URL:** Defined in `prisma7.config.ts` via `env('DATABASE_URL')`, NOT in `schema.prisma`.
- **After schema changes:** Run `pnpm prisma generate` then `pnpm prisma migrate dev --name <description>`.

## Database

- **Engine:** PostgreSQL via `@prisma/adapter-pg`.
- **Connection:** `DATABASE_URL` in `.env` → `postgresql://postgres:viptel3562@localhost:5432/nest_tareas`.
- **Naming:** Spanish in code (`Usuario`, `Tarea`, `rol`, `estado`, `creadoEn`), mapped to Spanish tables (`usuarios`, `tareas`, `refresh_tokens`).
- **IDs:** `Int @id @default(autoincrement())` — all models use auto-increment integers.
- **Enums:** `Rol` (USUARIO, ADMIN), `EstadoTarea` (PENDIENTE, EN_PROGRESO, COMPLETADA), `Prioridad` (BAJA, MEDIA, ALTA).

## API endpoints

```
POST   /api/auth/register       → register (returns usuario + tokens)
POST   /api/auth/login          → login (returns usuario + tokens)
POST   /api/auth/refresh        → refresh accessToken via refreshToken
POST   /api/auth/logout         → invalidate refreshToken
GET    /api/usuarios            → list users (ADMIN only)
GET    /api/usuarios/:id        → get user by ID (any authenticated user)
PUT    /api/usuarios/:id        → update user (own profile or ADMIN)
PATCH  /api/usuarios/:id/rol    → change user role (ADMIN only)
PUT    /api/usuarios/:id/password → change password (own only)
DELETE /api/usuarios/:id        → delete user (ADMIN only)
POST   /api/tareas              → create task (assigns usuarioId from JWT)
GET    /api/tareas              → list tasks (filtered by ?estado=&prioridad=)
GET    /api/tareas/stats        → task counts by status
GET    /api/tareas/:id          → get task (own or ADMIN)
PUT    /api/tareas/:id          → update task (own or ADMIN)
DELETE /api/tareas/:id          → delete task (own or ADMIN)
GET    /                       → health check
GET    /api/docs                → Swagger UI
```

## Auth flow

```
Register/Login → { usuario, accessToken, refreshToken }
                       │
                       ▼
        Use accessToken in Authorization: Bearer <token>
                       │
                       ▼
        JwtAuthGuard validates → JwtStrategy looks up user in DB
                       │
                       ▼
        request.user = { id, email, nombre, rol }
                       │
                       ▼
        @CurrentUser() decorator extracts user in controllers
                       │
                       ▼
        RolesGuard checks @Roles(Rol.ADMIN) if present
```

- **Access token:** 1h expiration, signed with JWT_SECRET
- **Refresh token:** 24h expiration, signed with JWT_REFRESH_SECRET, stored in DB
- **Refresh flow:** Old token deleted → new pair generated (token rotation)
- **Logout:** Refresh token deleted from DB → cannot be used again

## Gotchas

- E2e tests spin up a real NestJS app. They use `supertest` and import `AppModule` directly.
- Default GET `/` returns "Hello World!" — update tests if you change the response.
- `nest-cli.json` sourceRoot is `src/`. New modules go there.
- `.env` is gitignored. Use env vars for config, not committed files.
- **Prisma generated code** lives in `src/generated/prisma/`. Never edit these files manually.
- **JWT expiresIn** requires `as any` cast in `JwtModule.registerAsync` due to type incompatibility with `StringValue`.
- **Owner checks:** tasks and users enforce ownership — users can only see/edit their own resources unless ADMIN.
- **Docker:** `dist/src/main.js` is the entry point (not `dist/main.js`).
- **Prisma generate:** Requires dummy DATABASE_URL during Docker build (no DB connection needed).

## Security rules (auth & authorization)

- **Never add `rol` or `usuarioId` fields to client-sent DTOs.** Role and owner are assigned server-side only.
- **Passwords:** always bcrypt (cost ≥ 10). Never plain text, never logged.
- **JWT:** sign with default `@nestjs/jwt` algorithm. Never disable signature verification.
- **Guards:** every endpoint that mutates or exposes data must pass `JwtAuthGuard`, and `RolesGuard` if role-based restriction applies.
- **Error messages:** login/register errors must never reveal whether an email exists.
- **Logging:** never print `JWT_SECRET`, `DATABASE_URL`, a full `access_token`, or passwords.
- **Secrets:** read from env vars only. Never hardcode or commit to GitHub.
- **Refresh tokens:** stored in DB (`refresh_tokens` table) with expiration. Invalidated on logout.
- **Role changes:** only via dedicated `PATCH /api/usuarios/:id/rol` endpoint (ADMIN only), never through general update endpoint.

  -e DATABASE_URL="postgresql://..." \

  -e JWT_REFRESH_SECRET="..." \

- Includes `prisma migrate deploy` in CMD (auto-migration on start)
